---
title: Set Up Judging from the CLI
description: Create a prize and scorecard, invite judges, and share project reviews fairly.
---

Start with one prize and a ready-to-use scorecard. Add other methods or rounds when you need them.

## Check What Is Ready

```bash title="Inspect judging"
hackathon judging setup inspect <event> --json
```

This returns prizes, scorecards, dates, judge progress, and the steps still needed. Use the event ID from `hackathon events list`.

## Start with a Prize and Scorecard

You can save the prize first and set up its scorecard later:

```bash title="Save a prize first"
hackathon prizes create <event> --name "Best overall" --value "$500" --style weighted_score
```

Judging stays unready until its scorecard is complete. Or save the starter prize and scorecard together:

```bash title="Save the starter setup"
hackathon judging setup configure <event> --starter --prize-name "Best overall"
```

The starter adds a prize when needed and four shared questions: Original idea, Does it work?, Easy to use, and Usefulness. Each uses a 0–10 scale and counts for 25% of the score. It does not replace existing scorecards. Existing events keep their rules until you save a change.

Set a judging window separate from the event dates. Include the time zone offset in each time:

```bash title="Set judging dates"
hackathon judging setup configure <event> \
  --opens-at 2026-09-12T09:00:00-04:00 \
  --closes-at 2026-09-12T17:00:00-04:00 \
  --timezone America/Toronto \
  --reviews-per-project 3 --reminders on --browse off
```

Use `--instructions "..."` for a note to judges. `--browse on` lets judges find more eligible projects beyond their assigned queue. Use `--file settings.json` or `--data '{"remindersEnabled":true}'` for a JSON settings object.

Setup saves check the current version. For scripts, pass `--expected-version` from inspection and reuse `--request-key` when retrying the same save.

## Invite Judges by Email

Preview up to 20 addresses, then send:

```bash title="Preview and send invites"
hackathon judging invitations batch <event> \
  --emails "alice@example.com,bob@example.com"

hackathon judging invitations batch <event> \
  --emails "alice@example.com,bob@example.com" --send \
  --request-key invite-batch-20260912
```

The preview shows who can be added, invited, or needs attention. People already registered for this event can be added directly. Everyone else gets an acceptance link. Draft events queue invitations until the event goes live. Read each result's outcome and delivery state; a queued invitation has not been sent.

To limit judges to certain prizes or rooms, add `--prizes <prize-id,...>` or `--rooms <room-id,...>`. Find prize IDs with `hackathon prizes list`. Reuse the same request key when retrying a batch.

```bash title="Review invitations and reminder eligibility"
hackathon judging invitations list <event>
hackathon judging invitations remind <event> --emails "alice@example.com"
hackathon judging invitations remind <event> --emails "alice@example.com" --send
```

Reminder previews explain when an invitation cannot be reminded yet. Judges also receive scheduled updates when their work is ready and before the deadline. Completed judges are left out of work reminders.

## Share the Project Reviews

Once projects are submitted and judges have accepted, preview the assignments:

```bash title="Preview assignments"
hackathon judging assignments preview <event> --reviews-per-project 3 --json
```

The target is reviews per project **for each prize**. The preview shows coverage, each judge's workload, and any shortage of eligible judges. It respects prize and room limits, excludes a judge's own team, and keeps existing assignments and reviews.

Copy the preview version into the apply command:

```bash title="Apply the reviewed plan"
hackathon judging assignments apply <event> \
  --reviews-per-project 3 --expected-version <preview-version> \
  --request-key distribution-20260912
```

Use the same target, version, and request key when retrying. A changed setup requires a fresh preview. A weighted review can cover several eligible prizes without asking the judge to repeat shared questions.

### Adjust One Judge's Projects

```bash title="Manual assignments"
hackathon judging judges list <event>
hackathon judging assignments list <event>
hackathon judging assignments create <event> --judge <judge-id> --submission <project-id>
hackathon judging assignments delete <event> <assignment-id>
```

Submitted reviews cannot be removed. The older `judging auto-assign <event> --per-judge 5` command remains available; its number caps projects per judge for each prize. Use preview and apply for a reviews-per-project target.

Add `--prize <prize-id>` to `assignments create` for a pass/fail or sort-group scorecard. For favorite picks, set which prizes and rooms the judge can review:

```bash title="Change an accepted judge's scope"
hackathon judging judges scope <event> <judge-id>
hackathon judging judges scope <event> <judge-id> --prizes <prize-id,...> --rooms <room-id,...>
hackathon judging judges scope <event> <judge-id> --prizes all --rooms all
```

Scope changes keep existing reviews. A judge who has submitted reviews keeps their original prizes and rooms. Unsubmitted projects that become ineligible leave the judge's queue; the organizer can remove those old assignments.

## Change Scorecards or Add Rounds

```bash title="Inspect and change scorecards"
hackathon judging scorecards list <event>
hackathon judging criteria create <event> --name "Clarity" --min-score 0 --max-score 10 --weight 25
hackathon judging scorecards update <event> <prize-id> --file scorecard.json
```

`judging criteria` manages shared categories. `scorecards update` accepts prize settings and prize-specific categories through the same API as the app. Keep existing category IDs in edits. Supported `--style` values are `weighted_score`, `gate_check`, `bucket_sort`, `judges_pick`, and `crowd_vote`. Other options include `--round`, `--judge-scope all|selected`, and `--max-picks`.

For example, a gate-check scorecard file can contain:

```json title="scorecard.json"
{"judgingStyle":"gate_check","criteria":[{"name":"Does the demo work?"}]}
```

Once a review is submitted, its scoring rules and category wording stay fixed. Prize names and reward descriptions can still change. Use a new round for a new scoring prize or scorecard.

```bash title="Optional rounds"
hackathon judging rounds list <event>
hackathon judging rounds preset <event> --preset shortlist --data '{"advanceTopN":5}'
hackathon judging rounds update <event> <round-id> --opens-at 2026-09-12T13:00:00-04:00 --closes-at 2026-09-12T17:00:00-04:00
hackathon judging rounds activate <event> <round-id>
hackathon judging rounds complete <event> <round-id>
hackathon judging rounds candidates <event> <round-id>
hackathon judging rounds advance <event> <round-id> --file advancement.json
```

Round dates override event judging dates. Leave them unset to use the event window. Round advancement uses the existing API rules; inspect candidates before choosing who moves on.

The old `judging levels` aliases return guidance because their former API route is unavailable. Use scorecard inspection and editing for supported settings; separate rubric-level edits are not exposed by these commands.

## Check Progress and Results

```bash title="Review progress and winners"
hackathon judging setup inspect <event>
hackathon judging judges list <event>
hackathon judging assignments list <event> --json
hackathon judging pick-results <event>
hackathon results calculate <event>
hackathon results get <event>
```

After reviewing the winners, publish with `hackathon results publish <event>`.
